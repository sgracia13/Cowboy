How it works.

01

Every pull request is sorted as it arrives.

Easy, normal or careful, by fixed rules, with the reasons written on the pull request. It’s a starting point, not a verdict.

02

It watches what happens after merge.

Reverts, broken main, follow-up fixes and incidents, traced back to the pull request. It can rate your last 90 days on day one.

03

Then it checks which rules earn their place.

Each rule is compared with “largest first”, “most files touched” and a random pick. The ones that don’t earn their place show up, so you can stop paying for them.

We ran the test on our own rules first.

Before each round we wrote down what would count as a win, then tested on about 28,000 merged pull requests from eleven public repos. Cowboy's careful pen didn't beat “largest first” or chance, and counted by lines read it did worse than chance. The easy pen mostly held up. We publish all of it, and the same test runs on your repo, where the answer may be different.
